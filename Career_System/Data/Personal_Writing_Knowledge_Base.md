# Personal Writing Knowledge Base v0.9 — 추가 검증 항목 사용자 확인 갱신본

> 이 문서는 **기존 Career Master Profile을 대체하지 않는다.** 과거 지원서에 나타난 질문 대응 방식, 판단 근거, 해석의 차이, 본인다운 표현의 재활용을 지원하는 *보조 검색 인덱스*다.
>
> 자료 상태: 2026-10-04 기준 Google Drive `Career_Originals/Applications/2026`의 18개 기업 지원서 아카이브를 전수 대조했다. 17개 기업은 자기소개서 원문을 문항 단위로 색인했으며, 신한은행의 당시 확보본에는 자기소개서 본문이 포함되어 있지 않아 문항 색인을 생성하지 않았다. 기존 PDF-only 지원서는 원본 PDF를 그대로 보존한 채 검색·대조를 위한 Markdown 보조 아카이브를 추가했다. 이미지형 PDF를 직접 판독해 생성한 MD는 검색 보조본이며 문장·수치의 최종 기준은 원본 PDF다. DB Inc. 원문은 아카이브에 **미제출 작성본**으로 기록되어 있으므로 제출 완료본으로 간주하지 않는다. 원문은 공개 저장소 외부인 연결된 Google Drive `Career_Originals/Applications/`에서 관리하며, Private GitHub의 `Career_System/Data/Essay_Archive/`에 별도 백업한다. Google Drive의 실제 파일이 해당 채팅에서 열람되지 않을 수도 있다.
>
> 데이터 관리: 자기소개서 재활용에는 생년월일, 전화번호, 이메일, 주소, 사진, 수험번호가 필요하지 않으므로 이 문서에 넣지 않았다.

## 1. 저장소 규칙 및 우선순위

1. 사실의 기준: **Career_Master_Profile.md** 또는 사용자가 이후 확정한 최신판.
1-1. 필요할 때 **Experience_Story_Bank.md**에서 기존 사건 ID와 서술 맥락을 찾는다. 파일명은 유지하되, 사건 카드는 사용자 승인 없이 자동 추가·수정하지 않는다. Story Bank의 서술을 새로운 객관적 사실로 자동 승격하지 않는다.
2. 과거 지원서: **어떤 회사·문항에서 경험을 어떻게 설명했는지**를 보여주는 작성 당시의 기록. 새로운 사실을 무조건 확정하지 않는다.
3. Insight Card: 과거 글에서 발견한 개인의 판단·동기·갈등·학습에 대한 **재사용 가능한 해석 후보**. 지원자가 현재도 동의하는지 중요한 경우 확인한다.
4. Voice Guide: 문장 그대로 복제할 규칙이 아니라 사용자에게 자연스러운 **사고 전개 및 문체의 참고값**.
5. 특정 기업/산업을 위해 덧붙인 입사 후 포부를 다른 기업에 일반화하지 않는다.
6. 미확인 사건·객관적 성과·실제 직접 발언을 사실로 확정하지 않는다. 감정·동기·문제의식의 창의적 표현은 사용자 검토용 서술 후보로 제안할 수 있다.

원문 파일은 이 **Public GitHub 저장소에 게시하지 않는다.** 아래의 문항 ID는 실제 원문에 접근하도록 돕는 색인일 뿐 원문을 대체하지 않는다. 연결된 Google Drive가 접근 가능하면 해당 파일을 직접 열람하고, 실패하면 권한 있는 Private GitHub의 동일한 백업본을 조회한다. 두 경로 모두 접근할 수 없으면 필요한 원문을 해당 채팅에 요청한다.

- 선택: 실제 회의와 투표 절차를 분석한 뒤 요구사항과 기능을 다시 정의하고, 사용자 시연과 피드백을 거쳐 새로운 업무 방식으로 정식 도입.
- 추출된 관점: **DX의 가치는 기존 일을 단순히 디지털 화면으로 옮기는 것이 아니라, 실제 업무 흐름을 분석해 불필요한 단계를 줄이고 더 나은 프로세스로 재구성하는 데 있다.**
- 추천 의도: DX, 업무혁신, PM, 요구사항 분석, 프로세스 개선, 서비스 도입.
- 출처: LGE26-Q2, HD26-Q1, CJ26-Q2.
- 구분: `INS-010`은 새 방식을 실제 사용까지 연결하기 위한 **신뢰 확보**가 중심이고, 이 카드는 무엇을 디지털화해야 하는지를 결정하는 **업무 프로세스 재설계**가 중심이다.

## 4. Voice Guide (과거 작성본에서 관찰한 경향; 사용자가 승인하기 전까지 추론)

- 강점: 직접 겪은 문제 상황으로 시작하여 **왜 기존 방식이 불충분했는지** 설명하는 전개.
- 강점: 기술명 그 자체보다 사용 목적, 사람 간 이해관계, 의사결정의 이유를 연결.
- 강점: 데이터(사용자·집계 시간·리뷰)를 이야기의 종결 근거로 사용하는 경향.
- 자연스러운 지점: '막연히 좋은 기술을 쓰고 싶다'가 아닌 '사용자의 어떤 문제를 바꾸고 싶었다'로 자기 동기를 설명할 때.
- 줄일 습관: 유사한 결론 문장 반복(예: '이 경험을 통해 ~ 배웠습니다'만으로 단락 종결), 조직마다 같은 장래포부 붙이기, 직무 단어를 서술 전개보다 앞세우기.
- 문장 작성 지침: ① 상황의 구체적 제약 ② 지원자가 실제로 고민한 두 대안 ③ 선택 이유 ④ 직접 행동 ⑤ 검증 가능한 결과 ⑥ 그때 달라진 판단 중 문항에 필요한 부분만 선택.
- 표현 재사용: 과거 표현은 같은 판단·감정·맥락이 실제로 유지되고 문항 취지에 맞는 경우에만 일부 차용. 통째 복제하지 않는다.
- GS26-Q2에서 드러난 구체화: 추상적인 설득 능력이 아니라 **처음 요청이 먹히지 않았던 이유 → 실제 참여자별 조건 재설계**처럼 실패한 시도와 선택의 대비가 있을 때 본인다운 설명이 살아난다.
- GS26-Q4에서 드러난 균형: **전후 지표를 제시하면서도 인과 한계와 AI 기술의 품질 한계**를 함께 인정해, 사용자를 이해하는 실무적 판단을 드러낸다.

## 5. 질문 유사도 검색 규칙

검색 순서: **사용자가 승인한 문항별 경험 배정표 → 질문의 평가 의도 → 경험 ID → 그 경험에서 쓰인 판단·갈등·인사이트 → 글자 수와 문체**.

- 다른 경험으로 갈아타지 않는다. 같은 경험의 과거 답변이 없다면 비슷한 추상 역량 표현만 참고하고 본문 근거는 최신 프로필에서 찾는다.
- '문제가 생겼을 때 어떻게 대응?'과 '협업 중 갈등?'은 둘 다 전자투표를 소재로 쓰더라도 **상황의 초점**이 달라야 한다. 전자는 위험 판단·대응, 후자는 의견 차이·조정 과정을 중심으로 쓴다.
- 재사용 전 출력: 선택한 과거 문항 ID, 차용할 **사고의 관점**, 차용하지 말아야 할 **산업별 포장/미확인 사실**, 새로운 질문에 맞는 차별화 이유.

## 6. 이 파일의 갱신 범위

- 신규 제출/작성 원문의 문항 ID, 당시 직무, 질문 의도, 재사용 가능한 사고 관점, 출처만 추가한다.
- 사실 충돌의 상세 해결 기록은 `Review/Verification_Queue.md` 하나에만 유지한다. 인사이트 카드에 필요한 경우 `VERIFY-XX` 식별자만 링크한다.
- Experience Story Bank는 사건 설명이 필요할 때 선택적으로 참고한다. 새 사건 카드를 추가·수정하려면 실제 원문 및 사용자 확인을 바탕으로 별도 승인을 받는다. 사용자 승인에 따라 갱신할 수 있다.
- 이전 검토본의 충돌 확인 기록은 Review에 보존한다. 이 KB에는 문항 색인·서술 인사이트와 현재 참조 범위만 유지하며, 원문 추가 시 전체 인덱스와 중복 여부를 점검한다.
