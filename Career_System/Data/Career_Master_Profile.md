> **Version:** 1.6
> **Last Updated:** 2026-10-04
> **프로젝트 코드 근거 확인일:** 2026-09-20
> **Owner:** 문준호  
>
> 이 문서는 회사별 지원서 문구가 아니라, 실제 경험·행동·기술·성과를 통합한 기준 원본이다.  
> 이후 직무 추천, 자기소개서, 경험기술서, 면접 준비에서는 이 문서를 우선 기준으로 사용한다.

## 0. 정보 관리 원칙

### 상태 정의

- **[확정]** 사용자 직접 확인 또는 프로젝트 저장소·증빙으로 확인한 사실. 과거 지원서만으로 새 사실을 자동 확정하지 않는다.
- **[추론]** 확정 사실에서 합리적으로 해석할 수 있으나 사용자가 직접 확정하지 않은 내용
- **[미확인]** 관련 정보가 없거나 구체성이 부족한 내용
- **[충돌]** 서로 다른 자료에서 값이 다르게 나타나는 내용
- **[정정/폐기]** 과거 정보보다 이후 사용자 확인값이 우선하는 내용

### 사용 원칙

1. 지원자가 실제로 하지 않은 경험을 만들어내지 않는다.
2. 프로젝트명만 보고 역할이나 역량을 확대 해석하지 않는다.
3. 팀 프로젝트의 전체 성과와 본인 직접 기여를 구분한다.
4. 기술 사용은 `실서비스/제품`, `프로젝트`, `수업/실습`, `단순 사용`으로 구분한다.
5. 자기소개서의 표현보다 실제 행동·구현·수치를 우선한다.
6. 동일 경험은 회사별 지원서마다 중복 등록하지 않고 하나의 canonical record로 통합한다.
7. 전화번호, 이메일, 상세주소, 등록번호 등 취업 분석에 불필요한 개인정보는 이 문서에 저장하지 않는다.
8. 전공수업·교과목 이수는 원칙적으로 **학업 배경과 기초지식의 증거**로 취급한다. 수업을 들었거나 높은 성적을 받았다는 사실만으로 주도성, 깊은 몰입, 실전 문제해결 역량, 해당 분야에 대한 강한 열정을 추론하지 않는다.
9. 수업 중 수행한 일반적인 과제·실습은 별도 근거가 없다면 `수업 범위의 학습 경험`으로 본다. 실제 제품·서비스, 독립 프로젝트, 조직 활동과 같은 무게의 경험으로 평가하지 않는다.
10. 자기소개서·에세이·면접의 핵심 경험 소재는 실제 프로젝트·제품·조직 활동을 우선한다. 전공수업은 JD의 전공지식 충족 여부를 확인하거나 프로젝트의 기술적 기반을 보조할 때 주로 사용한다.
11. 지원서가 명시적으로 수강과목·전공지식·학업 경험을 요구하거나, 사용자가 특정 수업 프로젝트를 별도의 주도적 경험으로 확정한 경우에만 해당 수업을 주요 경험 소재 후보로 올린다.

# 10. 현재 증거 공백

> 증거가 현재 자료에 없다는 뜻이며 해당 경험이 실제로 없었다는 단정이 아니다. **직무별 경쟁력에 대한 평가는 이 파일이 아닌 해당 JD 분석 단계에서 한다.**

- **[현재 기록]** 정규 기업 인턴/직장 경력: 현재까지 확인되지 않음.
- **[확정]** 영어 OPIc IM2. 직무별 요구 수준과의 비교는 공고 조사 시 수행한다.
- **[현재 증거 부족]** 논문, 독립적인 모델 학습 연구, 대규모 ML 파이프라인을 주도했다는 근거.
- **[현재 증거 부족]** 대규모 실서비스 트래픽, 프로덕션 운영 장애 대응, 프로덕션 관측성, 분산 시스템 운영 이력.
