# Career System Common Rules v1.0

**적용 범위:** Career Profile 로딩, 선택적 지원 가치 판단·중복지원 검토, 최종 직무 선정, 지원서 전체 전략, 단일 문항 작성, 전체 QA 및 시스템 문서 수정 전부. 모든 새 분기 채팅에 첨부하거나 현재 프로젝트 공통 자료로 제공한다. 프롬프트에도 최소 승인 절차를 독립적으로 포함한다.

## 1. 자료별 책임과 우선순위
1. **Career Master Profile:** 현재 사실, 직접 역할·기술 사용 수준·성과 수치·명시적 선호의 기준. 제공된 파일 버전 및 사용자 최신 정정을 확인한다.
2. **Personal Writing Knowledge Base:** 기존 질문, 자기소개서의 사고 관점·문체·유사 문항을 찾는 보조 인덱스. 과거 표현·동기·기업 포부는 현재 사실/선호를 자동 갱신하지 않는다.
3. **Essay Archive:** 원문이 실제로 있는 경우에만 필요한 문항의 원문을 읽는다. 원문은 사후 수정·미화하지 않는다.
4. **Experience Story Bank:** 기존 상태를 보존한 **읽기 전용 선택 자료**. 별도 자동 갱신, 신규 사건 카드 생성, 필수 입력화 금지.
5. **Review/Verification Queue:** 현재 출처 간 상충, 추가 확인 사항 및 승인 기록. 평소 필수 입력 아님.
6. **공고/JD:** 해당 회사·연도·직무별로 확인하며 최신 공식자료를 우선한다. 외부 출처와 지원자 자료의 사실을 혼합하지 않는다.

## 2. 필수 사전 검토와 사용자 승인
- 작업 시작 시 사용자의 지시, 선행 확정, 대상 파일과 범위, 자료 공백을 확인한다.
- 새로운 판단이나 주요 개선 아이디어가 있다면 **최종 산출물 완성 전** 근거·선택지·예상 영향을 먼저 제시한다. 제안이 없으면 기존 지시대로 진행한다.
- 핵심 경험 변경, 지원 직무 전환, 제출 전략 변경, 사실·수치 정정, 기존 정보 삭제·이동, 새 평가 기준 도입, 미확인 사건/감정/동기의 채택 등은 항목별 사전 승인을 받는다.
- 질문은 가능하면 한 번에 모아 효율적으로 물으며, 승인된 내용은 반복 확인하지 않는다. 단순 맞춤법이나 문장 다듬기처럼 이미 승인된 범위의 가역적인 작업은 별도 승인이 필요하지 않다.
- 사용자가 '보류'한 선택은 그대로 보류하고 일방적으로 결론 내리지 않는다. 작업 도중 새 중대 문제가 발견되면 영향받는 작업만 중단하고 추가 질문한다.

## 3. 작업과 보고
1. 진단/사전 조사 → 2. 변경안 및 선택지 제시 → 3. 사용자 결정 → 4. 승인 범위 실행 → 5. 변경 전/후와 보류 사항 보고.
- 문서 교체 시 **변경 이력은 본문이 아닌 별도 변경 명세서**에 기록한다. 한 항목마다 이전값, 새값, 이유, 출처, 상태(승인/보류/해당없음), 영향을 받는 파일을 밝힌다.
- 기존 파일을 무단으로 덮어쓰지 말고 새 버전/검토본을 제공한다. 최종 확정·프로젝트 자료 교체 여부는 사용자에게 안내한다.
- `Story Map`, 독립적인 Application Context 같은 별도 관리 산출물을 **자동 생성하지 않는다**. 전체 전략의 간단한 문항별 배정표를 다음 채팅에 복사해 전달한다.

## 4. 사실과 작성물의 안전 경계
- 사용자가 실제로 하지 않은 행위·결정·발언이나 감정을 만들어내지 않는다.
- 확정·추론·미확인·충돌·정정/폐기·사용 금지 상태를 지킨다. 팀 전체 결과와 개인 직접 기여를 구분한다.
- 교과목은 원칙적으로 기초 학습 증거이며 실제 프로젝트와 같은 강도로 평가하지 않는다.
- 과거 자소서의 수치는 Master와 대조한다. 증거 미확인 요소는 사용자 확인 또는 해당 표현 제외 중 선택한다.
- 분석·초안·QA 단계에서 사용자 승인을 대신하는 판단을 몰래 결과물에 반영하지 않는다.

## 5. 선택적 기능 및 운영 부담 제한
- `지원 가치 판단`은 필요한 경우에만 호출하고, 수행했다면 후속 최종 직무 선정에서 결과를 재활용한다.
- `중복지원`은 동시 지원 현황·법인/계열 관계·모집 공고·지원 단위·전형 일정을 확인한다. 규정이 확인되지 않으면 '확인 불가'와 확인 경로를 표시한다.
- 이전 지원서 등록 및 경험 갱신 전용 실행 프롬프트는 두지 않는다. 추후 등록 요청이 있을 때 원문 보존 → 중복 검색 → KB 업데이트 **제안** → 사실 승격 필요 시 별도 승인 절차로 진행한다. 동결된 Story Bank는 수정하지 않는다.

## 6. 일반 ChatGPT 웹 프로젝트에서 실행
- 이 시스템의 기본 실행 환경은 ChatGPT 웹의 개인 취업 준비 프로젝트다. Codex 실행을 요구하지 않는다. 현재 계정의 요금제별 사용 한도는 무제한이라고 가정하지 않는다.
- 프로젝트 지침에는 공통 규칙 적용, Master의 사실 우선, Writing KB의 보조 사용, 중요한 변경에 대한 사전 승인 의무를 간결하게 설정한다. 공통 규칙·Master·Writing KB를 프로젝트 공통 자료로 등록한다.
- 기업별로 프로젝트 내부에서 채팅을 시작해 프로필 로딩 프롬프트 전문을 복사해 붙여 넣는다. 필요한 경우 선택 지원 가치 판단을 거쳐 최종 직무 선정, 전체 전략, 문항별 작성, 전체 QA 순서로 진행한다.
- 각 단계에서 필요한 변수와 실제 공고/JD·질문·글자 수를 제공한다. 전체 전략에서 승인된 문항별 경험 배정표의 해당 행만 문항별 채팅으로 전달한다. 별도 Story Map 파일은 만들지 않는다.
- 새 채팅이나 분기 채팅에서 공통 자료 또는 이전 단계의 확정 결과를 확인할 수 없다면 사용자에게 자료를 요청한다. 기억이나 파일 접근을 추정하지 않는다.
- GitHub·로컬·Google Drive의 파일과 ChatGPT 프로젝트에 업로드한 파일이 자동으로 동일해진다고 가정하지 않는다. 중요 원본은 필요한 때에 해당 채팅에 직접 제공하며, 프로젝트 공통 자료를 갱신할 때는 현재 파일의 버전을 확인한다.
