## 4. 반영 규칙

1. 해결된 사실도 기존 지원서 원문을 소급 수정하지 않는다.
2. 직접 사용자 확인이나 실제 코드·운영 자료 검증이 끝나면 상태·출처·확인일을 갱신한다.
3. 다른 MD 파일에서 '[미확인]'을 '[확정]'으로 바꾸어야 한다면 해당 파일별 변경안을 따로 제시하고 승인받는다.
4. 상태가 미해결인 객관적 역할·일자·수치·기술 상세는 신규 지원서에 확정 사실처럼 사용하지 않는다.
5. **사실의 미기재는 사실 부정을 의미하지 않는다.** 같은 경험의 세부 사실이라도 문항 의도·글자수·전략에 따라 어떤 지원서에는 포함하고 다른 지원서에는 생략할 수 있다. 따라서 자소서 간 '포함/미포함'만으로 충돌을 만들지 않는다.
6. 해결된 과거 오기·예정값은 원문을 소급 수정하지 않고 Queue에 재사용 금지 또는 현재 canonical 값을 명시한다.
