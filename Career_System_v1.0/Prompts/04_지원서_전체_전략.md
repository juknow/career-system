# 지원서 전체 전략 설계

앞선 대화에서 채용공고와 직무를 분석했고, 사용자가 아래 직무를 **최종 확정한 후에만** 이번 단계를 실행한다. 현재 승인된 Career Master Profile은 사실의 기준이며 Writing Knowledge Base는 과거 자소서 색인·해석·문체의 보조 자료다. 읽기 전용 Story Bank는 특별히 필요한 과거 사건이 있을 때만 참고한다.

공통 운영 규칙(`Career_System_Common_Rules.md`)을 적용한다. **핵심 경험의 배치와 지원자 전체 이미지에 관한 새로운 제안은 완성 전에 사용자에게 보여주고 승인받는다.**

- 회사: {회사명}
- 공고: {공고명}
- 최종 지원 직무: {사용자가 확정한 직무명}
</SELECTED_JOB>

상위 대화의 Career Master Profile, 해당 회사 조사 결과, JD 분석, 요구 역량 검토, 직무를 선택한 이유, 증명할 수 있는 강점과 증거 공백을 활용한다. 이번 단계는 자소서를 바로 쓰지 않고 **전체 입력란과 문항의 경험 배치를 정하는 작업**이다.

{지원서 전체 항목}

## 1. 지원서가 검증하려는 것 분석
각 항목의 평가 의도, 입증해야 할 역량, 지원자에게 확인하고 싶은 구체적 행동과 증거를 분석한다. 실제 회사의 평가 기준이 공개되지 않은 경우 **평가 의도에 대한 분석**이라고 명시하고 확정 사실처럼 말하지 마라.

## 2. 경험 전체 후보군 검토
Career Master Profile의 실제 경험을 검토한다. 모든 경험을 억지로 사용하지 마라. 경험별 직무 연결성, 회사 연관성, 차별적 근거, 정량 성과, 직접 기여, 설명 가능성, 다른 문항과 중복 가능성, 면접 확장성을 비교한다. 과거에 많이 사용한 자소서 경험이라는 이유만으로 우대하지 마라.

## 3. 문항별 경험 배정
사용자가 승인하기 편한 **간단한 배정표 하나만** 만든다. 각 문항의 평가 의도, 핵심 경험, 필요 시 보조 경험, 증명할 직접 행동과 핵심 성과, 강조할 역량을 결정한다. 사용자가 승인한 후에야 확정된 배정표로 취급한다.

별도 관리 파일을 생성하지 않는다. 승인된 배정표에서 각 문항의 내용을 복사해 해당 작성 채팅에 전달한다.

경험을 먼저 배정하고 나서 Writing KB에서 해당 경험·질문과 관련된 과거 문항 ID와 유용한 인사이트만 찾아 배정표 아래에 간단히 연결한다. 과거 문장과 업종별 포부를 무단 재사용하지 않는다.

## 4. 자소서 외 입력항목 전략
- **프로젝트:** 실제 공고에 맞는 항목 선택, 배치 순서, 직접 한 일과 수치 중심.
- **대내외활동:** 직무 관련 행동/성과 위주로 정리.
- **교육:** 외부 실무교육과 일반 Coursework 구분; 학점을 실무성과처럼 과장하지 않음.
- **기술:** 실제 사용 수준 구분.
- **수상/자격/어학:** 직무 요건과 사실성 우선.

## 5. 경험 중복 관리
동일 경험을 여러 문항에 쓸 수는 있지만 사건·직접 행동·입증 역량이 실제로 구분되어야 한다. 같은 지표·똑같은 결론 반복을 피한다. 경험을 바꿔야 한다고 판단되면 먼저 제안하고 사용자 승인을 받는다.

## 6. 지원자 전체 이미지
지원서 전체에서 사실에 기반해 일관되게 보여줄 역량·이미지를 최대 3개 **후보로 제안**한다. 사용자의 선택을 받은 뒤 각 항목의 역할을 점검한다. 과거 다른 업종 지원서의 포지셔닝을 자동 채택하지 않는다.

## 7. 부족한 요소 처리
JD에서 확인되지만 현재 입증 근거가 약한 항목에 대해 전환 가능한 실제 경험의 활용, 기초지식 보조, 면접 준비, 과도한 강조 생략 등의 선택지를 제시한다. 미확인 사실을 꾸며 보충하지 않는다.

## 8. 출력 형식
A. 지원서가 확인하려는 역량
B. 지원자 포지셔닝 **제안**
C. 반드시 검토할 실제 경험
D. 사용하지 않아도 되는 경험과 이유
E. **문항별 경험 배정표 하나**

| 항목/문항 | 평가 의도(분석) | 핵심 경험 | 보조 경험 | 보여줄 직접 행동 | 입증 가능한 성과/역량 | 관련 과거 문항 ID |
|---|---|---|---|---|---|---|

F. 프로젝트/활동 입력 전략
G. 기술/교육/자격 입력 전략
H. 경험 중복 및 출처 충돌 위험
I. 부족한 역량 보완/방어 선택지
J. 문항별 작성 우선순위
K. 지원서 전체 핵심 메시지 **제안 및 승인 질문**

**필수 승인 단계:** 전체 배정표와 지원자 이미지를 먼저 보여주고 사용자에게 승인·수정·보류를 요청한다. 승인 후에만 후속 단일 문항 작성 단계에서 확정 배정표로 사용한다.
