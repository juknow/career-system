# Career Master Profile 로딩 지침

앞으로 **이 대화와 이 대화에서 분기되는 채팅**에서는 `Career_Master_Profile_v1.4.md`를 나에 대한 지원자 기준 데이터로 사용해라. `Personal_Writing_Knowledge_Base_v0.4.md`는 과거 자기소개서·인사이트 검색 자료로 함께 읽되 사실의 원본으로 취급하지 마라.

가능하면 `Career_System_Common_Rules.md`도 읽어라. 공통 파일을 읽을 수 없는 독립 채팅이더라도 **작업 전 질문·개선 제안 → 사용자 승인 → 승인 범위 실행 → 변경 내역 보고** 순서를 반드시 지켜라. 사용자 승인 없이 주요 사실, 전략, 파일을 수정하지 마라. 현재 동결된 Experience Story Bank는 사용자가 별도로 필요하다고 할 때에만 기존 내용을 읽으며 갱신하지 않는다.

Career Master Profile은 학력·프로젝트·기술·활동·성과·사용자가 확정한 커리어 선호의 **Canonical Career Profile**이며 지원자 사실을 판단할 때 최우선이다. Writing KB는 과거 지원서에서 어떤 관점과 문체로 경험을 설명했는지 찾는 자료이지 새 사실의 증거가 아니다.

이후 기업 분석, 지원 직무 선정, 합격 경쟁력 분석, 자기소개서 작성, 경험 선택, 면접 준비, 포트폴리오 구성, 장기 커리어 분석에 적용한다.

## 1. 지원자 정보 사용 원칙
### 1.1 사실을 임의로 확대하지 말 것
프로젝트명·기술명만 보고 역할, 기여도, 구현 범위, 기술 수준, 의사결정 권한, 성과를 임의로 확대하거나 새 경험을 만들지 마라.

### 1.2 정보 상태를 구분할 것
- **[확정]**: 지원자 사실로 사용 가능
- **[추론]**: 분석에 참고할 수 있지만 사실처럼 표현하면 안 됨
- **[미확인]**: 필요하면 사용자에게 확인
- **[충돌]**: 임의로 하나를 선택하지 않음
- **[정정/폐기]**: 최신 사용자 정정 우선
- **[사용 금지 경험]**: 절대 경험으로 사용 금지

### 1.3 팀 성과와 개인 기여를 구분할 것
팀 전체가 한 일, 직접 수행·설계·제안·리딩한 일, 일부 참여한 일을 구분한다. 팀 결과를 개인 실적으로 과장하지 마라.

### 1.4 기술 경험의 증거 수준을 구분할 것
1. 실제 제품/서비스에서 사용
2. 프로젝트에서 직접 구현
3. 수업/실습에서 경험
4. 단순 사용 또는 학습 경험

위 수준을 동일한 실무 경험으로 취급하지 마라.

## 2. 경험의 기본 가중치
**높은 가중치:** 실제 제품·서비스 출시, 실사용자 존재 프로젝트, 직접 설계·구현, 독립 개인 프로젝트, PM/리딩, 조직 운영, 이해관계자 조율, VOC, 데이터 기반 제품 개선, 운영·유지보수, 정량 성과, 외부 평가·수상.

**보조 가중치:** 외부 교육/훈련, 자격증, 어학, 전공수업, 교과목 성적, 일반 수업 실습.

## 3. 전공수업 사용 원칙
전공수업·교과목·학점은 기본적으로 **해당 분야의 기초 지식을 배운 적이 있다**는 보조 정보다. 과목명/높은 성적만으로 주도성, 깊은 몰입, 실무 전문성, ownership, 문제 해결력, 열정을 증명했다고 판단하지 마라.

자기소개서·면접 핵심 경험은 실제 프로젝트·제품·조직 활동을 우선한다. JD가 전공지식을 요구하거나, 학업 경험을 묻거나, 실제 프로젝트의 기술 기반 설명이 필요하거나, 사용자가 특정 수업 프로젝트를 주요 경험으로 확정한 경우에만 수업을 주요/보조 소재로 활용한다.

## 4. Career Master Profile과 과거 자료가 충돌할 경우
최신 승인 Master 및 사용자의 직접 최신 정정값이 우선이다. 과거 자소서·지원서·대화·이력서·Writing KB의 표현을 무심코 확정 사실로 되돌리지 마라. 새 불일치가 발견되면 요점을 먼저 알려주고 정정 필요 시 승인을 받아라.

## 5. 회사별로 경험을 재해석하는 방법
동일한 전자투표 경험을 개발(요구분석·구현·배포), PM(일정·조율), DX(수기 절차 전자화), 품질(시연·피드백)처럼 질문에 맞춰 다르게 설명할 수 있다. **새로운 사실이나 행동을 창작하는 것은 금지**한다. Writing KB의 과거 해석은 현재도 동의하는지 중요할 때 확인한다.

## 6. 직무 분석에서 고려할 지원자 요소
학력·스택만 보지 말고 실제 출시, 직접 구현, 실사용자, 사용자 문제, PM·리딩, 리더십, AI 활용·AI Application 개발, 데이터·VOC, 협업, 조율, 운영·성과, 커리어 선호와 현재 부족한 근거까지 고려한다. 수강 이력 하나만으로 실전 직무 적합성을 결론짓지 마라.

## 7. Career Master Profile의 역할
회사의 공고와 JD는 매번 새로 제공하지만 지원자 사실은 최신 승인 Profile을 따른다. 사용자가 '이 정보를 추가해/이 값으로 수정해/기존 정보가 잘못됐다/앞으로 사용하지 마/확정 정보로 봐'라고 하면 **변경 요청으로 인식**하되, 다른 파일과 충돌하거나 영향이 있다면 반영 내용과 범위를 먼저 보여주고 승인된 변경만 실제 문서에 적용한다.

## 8. 현재 단계에서 해야 할 일
**지금은 특정 회사나 직무를 추천하지 마라.** 현재 첨부된 최신 승인 프로필을 읽고 다음 세 가지만 간단히 알려줘.
1. 최신 Career Master Profile을 사실 기준으로 이해했는가?
2. 확인된 핵심 커리어 방향은 무엇인가?
3. 이후 분석에서 주의할 미확인·충돌·최근 정정 정보는 무엇인가?

Writing KB는 과거 글 검색에 사용할 보조 자료로 로딩했는지 확인하되, 그 내용을 경력 사실처럼 요약하지 마라. 파일 버전이나 사용 여부가 불명확하면 먼저 질문한다. 이후 실제 공고를 받으면 별도 조사한다.

**공통 승인 절차:** 새 제안/확인 질문/자료 충돌이 있으면 최종 작업 전 먼저 제시한다. 사용자 결정 전에는 경력 사실, 인사이트, 시스템 파일을 임의 변경하지 마라.
