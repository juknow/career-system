# Personal Writing Knowledge Base v0.4 — 확정 구조 적용본

> 이 문서는 **기존 Career Master Profile을 대체하지 않는다.** 과거 지원서에 나타난 질문 대응 방식, 판단 근거, 해석의 차이, 본인다운 표현의 재활용을 지원하는 *보조 검색 인덱스*다.
>
> 자료 상태: 현재 제공된 KB·GS 원문과 KT·현대엘리베이터·LIG·농협중앙회 PDF를 색인했다. 신한은행 제공 PDF에는 자소서 본문이 없다.
>
> 데이터 관리: 자기소개서 재활용에는 생년월일, 전화번호, 이메일, 주소, 사진, 수험번호가 필요하지 않으므로 이 문서에 넣지 않았다.

## 1. 저장소 규칙 및 우선순위

1. 사실의 기준: **Career_Master_Profile_v1.4.md** 또는 사용자가 이후 확정한 최신판.
1-1. 필요할 때 **읽기 전용 Experience_Story_Bank_v1.0.md**에서 기존 사건 ID를 참고할 수 있다. 이 파일은 신규 작성·자동 갱신하지 않는다. 해당 기록의 인사이트를 사실로 승격하지 않는다.
2. 과거 지원서: **어떤 회사·문항에서 경험을 어떻게 설명했는지**를 보여주는 작성 당시의 기록. 새로운 사실을 무조건 확정하지 않는다.
3. Insight Card: 과거 글에서 발견한 개인의 판단·동기·갈등·학습에 대한 **재사용 가능한 해석 후보**. 지원자가 현재도 동의하는지 중요한 경우 확인한다.
4. Voice Guide: 문장 그대로 복제할 규칙이 아니라 사용자에게 자연스러운 **사고 전개 및 문체의 참고값**.
5. 특정 기업/산업을 위해 덧붙인 입사 후 포부를 다른 기업에 일반화하지 않는다.
6. 출처 없는 직접 발언·감정·동기·내부 결정 과정을 새로 만들어내지 않는다.

- 추천 의도: 지원동기, 왜 개발자인가, 장기 커리어.
- 출처: KB26-Q1, HY26-Q1, **GS26-Q1(영업 직무의 특정 맥락)**.
- 주의: 게임 개발의 가치를 폄하하거나 모든 분야의 사용자 가치를 동일하게 단정하지 말고 현재 지원 JD에 맞게 표현.

### INS-009 · 상대가 실제로 얻는 것을 설계해야 협력이 만들어진다
- 중심 경험: KUCC 회장 `EXP-008`.
- 과거의 구체적 문제 서술: 교육 세션 진행자 확보에 어려움이 있었고, 단순 참여 요청으로는 호응을 얻지 못함.
- GS26-Q2에서 서술한 선택: 알럼나이를 멘토로 연결해 회원에게 커피챗·취업 조언 기회를 제공하고, 선배 후원금으로 세션 진행자에게 보조금을 지급하는 방식으로 서로 다른 참여자의 필요를 동시에 고려.
- 추출된 사고 관점: **상대가 왜 움직여야 하는가**를 파악하고, 참여자 모두에게 돌아갈 가치를 마련하는 것이 설득의 실행 조건.
- 적용 문항: 협력, 설득, 이해관계자 조율, 고객 니즈 파악, 리더십.
- 출처: **GS26-Q2**.
- 사실 경계: 금액·시행 횟수·인과관계는 현재 독립 증빙 없이 과거 지원서에서 확인된 서술. 2025 현대모비스 선정의 **단독 원인**이라는 주장은 금지.

### INS-010 · 변화의 완성 조건은 기술보다 새 방식에 대한 사용자 신뢰다
- 중심 경험: 전자투표 `EXP-002`.
- GS26-Q3의 질문 구성: 운영진(회의 안정성), 대표자(쉬운 화면), 개발팀(제한된 일정)이라는 **서로 다른 이해관계자의 성공 조건**을 제시.
- 선택: 개발 완료 후 일괄 공개가 아니라 **중간부터 사용자 시연을 거듭하고** 기능 우선순위를 조정.
- 개인적 해석: 변화는 아이디어 채택이 아니라 관계자의 신뢰를 확보해 **실제 사용**으로 이어질 때 완성.
- 적용 문항: 디지털 전환, 신뢰 형성, 협업, 리더십, 저항 극복, 서비스 도입.
- 출처: **GS26-Q3** (일정/검증 가치관은 `INS-003`과 중복되지 않게 취지 구분).
- 사실 경계: 실제 사용자 97명/안건당 30→5분/회의 최대 6→약1시간은 최신 프로필 기준. 추가 연장 월수는 계속 미확인.

## 4. Voice Guide (과거 작성본에서 관찰한 경향; 사용자가 승인하기 전까지 추론)

- 강점: 직접 겪은 문제 상황으로 시작하여 **왜 기존 방식이 불충분했는지** 설명하는 전개.
- 강점: 기술명 그 자체보다 사용 목적, 사람 간 이해관계, 의사결정의 이유를 연결.
- 강점: 데이터(사용자·집계 시간·리뷰)를 이야기의 종결 근거로 사용하는 경향.
- 자연스러운 지점: '막연히 좋은 기술을 쓰고 싶다'가 아닌 '사용자의 어떤 문제를 바꾸고 싶었다'로 자기 동기를 설명할 때.
- 줄일 습관: 유사한 결론 문장 반복(예: '이 경험을 통해 ~ 배웠습니다'만으로 단락 종결), 조직마다 같은 장래포부 붙이기, 직무 단어를 서술 전개보다 앞세우기.
- 문장 작성 지침: ① 상황의 구체적 제약 ② 지원자가 실제로 고민한 두 대안 ③ 선택 이유 ④ 직접 행동 ⑤ 검증 가능한 결과 ⑥ 그때 달라진 판단 중 문항에 필요한 부분만 선택.
- 표현 재사용: 과거 표현은 같은 판단·감정·맥락이 실제로 유지되고 문항 취지에 맞는 경우에만 일부 차용. 통째 복제하지 않는다.
- GS26-Q2에서 드러난 구체화: 추상적인 설득 능력이 아니라 **처음 요청이 먹히지 않았던 이유 → 실제 참여자별 조건 재설계**처럼 실패한 시도와 선택의 대비가 있을 때 본인다운 설명이 살아난다.
- GS26-Q4에서 드러난 균형: **전후 지표를 제시하면서도 인과 한계와 AI 기술의 품질 한계**를 함께 인정해, 사용자를 이해하는 실무적 판단을 드러낸다.

## 6. 질문 유사도 검색 규칙

검색 순서: **사용자가 승인한 문항별 경험 배정표 → 질문의 평가 의도 → 경험 ID → 그 경험에서 쓰인 판단·갈등·인사이트 → 글자 수와 문체**.

- 다른 경험으로 갈아타지 않는다. 같은 경험의 과거 답변이 없다면 비슷한 추상 역량 표현만 참고하고 본문 근거는 최신 프로필에서 찾는다.
- '문제가 생겼을 때 어떻게 대응?'과 '협업 중 갈등?'은 둘 다 전자투표를 소재로 쓰더라도 **상황의 초점**이 달라야 한다. 전자는 위험 판단·대응, 후자는 의견 차이·조정 과정을 중심으로 쓴다.
- 재사용 전 출력: 선택한 과거 문항 ID, 차용할 **사고의 관점**, 차용하지 말아야 할 **산업별 포장/미확인 사실**, 새로운 질문에 맞는 차별화 이유.

## 7. 이 파일의 갱신 범위

- 신규 제출/작성 원문의 문항 ID, 당시 직무, 질문 의도, 재사용 가능한 사고 관점, 출처만 추가한다.
- 사실 충돌의 상세 해결 기록은 `Review/Verification_Queue.md` 하나에만 유지한다. 인사이트 카드에 필요한 경우 `VERIFY-XX` 식별자만 링크한다.
- 이미 존재하는 사건 기록은 동결된 Experience Story Bank를 선택적으로 참고한다. 새 사건 설명이 필요하면 기존 지원서 원문을 먼저 확인하고, 사실 확정이나 별도 사건 기록의 신설은 사용자 승인 없이는 하지 않는다.
- 기존 `INS-001`~`INS-010`의 의미와 출처는 유지했으며, 기존 v0.3의 충돌 테이블과 변경 일지는 Review로 이동했다.
